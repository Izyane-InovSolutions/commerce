**Most consequential findings**

1. **Live webhooks and refunds are not implemented.** `UnifiedPaymentProvider.verifyWebhook()`, `refund()` and `getRefund()` explicitly throw/reject with `NotImplementedException`. Initialization and authenticated status polling do exist; polling applies gateway results through backend order/payment logic. The generic provider interface and fake-provider tests do not prove live webhook/refund support. This blocks full #22/#30/#43 acceptance and undermines closed parent #3. Evidence: [live adapter](https://github.com/Izyane-InovSolutions/commerce/blob/4e51b9a3f95cea84f25f524cd69dd0158bc495ee/services/commerce-api/src/modules/payments/unified-payment.provider.ts#L275), [trusted status application](https://github.com/Izyane-InovSolutions/commerce/blob/4e51b9a3f95cea84f25f524cd69dd0158bc495ee/services/commerce-api/src/modules/payments/gateway-payments.service.ts#L58).

2. **Customers cannot complete the delivered password-reset journey.** `requestPasswordReset()` creates a token hash but neither returns nor delivers the raw token; the comment explicitly defers delivery. Confirmation exists, but a normal user cannot obtain the token through this implementation. This affects closed #12 and #40. My earlier closure of #40 was too broad: I checked the client/API surfaces without catching this backend delivery gap. Recommend reopening it, or explicitly agreeing a linked delivery exclusion rather than calling the whole journey complete. Evidence: [reset request](https://github.com/Izyane-InovSolutions/commerce/blob/4e51b9a3f95cea84f25f524cd69dd0158bc495ee/services/commerce-api/src/modules/auth/auth.service.ts#L214).

3. **Admin stock adjustment violates parts of #25/#26.** The SQL guard checks `on_hand + delta >= 0`, not `>= reserved`. A state with 10 on hand and 8 reserved can accept delta -5, yielding -3 available. No migration constraint enforcing `on_hand >= reserved` was found. This is a source-derived counterexample, not a database reproduction. The admin controller passes no actor, the reason is optional, and the movement records `Math.abs(delta)`, so adjustment direction is lost. Seller inventory writes use stronger reserved-stock and signed-delta handling. Recommend reopening #25 and rechecking #26's recoverability criterion. Evidence: [admin adjustment](https://github.com/Izyane-InovSolutions/commerce/blob/4e51b9a3f95cea84f25f524cd69dd0158bc495ee/services/commerce-api/src/modules/inventory/inventory.service.ts#L418), [admin routes](https://github.com/Izyane-InovSolutions/commerce/blob/4e51b9a3f95cea84f25f524cd69dd0158bc495ee/services/commerce-api/src/modules/inventory/admin-inventory.controller.ts#L47), [seller stock write](https://github.com/Izyane-InovSolutions/commerce/blob/4e51b9a3f95cea84f25f524cd69dd0158bc495ee/services/commerce-api/src/modules/inventory/inventory.service.ts#L586).

4. **Shipment dedupe is not successful replay.** A failed delivery is retained as FAILED, but its next identical delivery returns immediately on a unique-key conflict; no retry processor was found. One provider exception during the shipment polling loop also prevents later shipments in that poll from being processed. Carrier booking occurs inside a DB transaction, without a stable provider idempotency/reconciliation input to recover an external success followed by DB failure. These are concrete #29/#50 gaps before adding live carriers. Evidence: [webhook failure/replay and poll loop](https://github.com/Izyane-InovSolutions/commerce/blob/4e51b9a3f95cea84f25f524cd69dd0158bc495ee/services/commerce-api/src/modules/shipments/shipments.service.ts#L493), [booking](https://github.com/Izyane-InovSolutions/commerce/blob/4e51b9a3f95cea84f25f524cd69dd0158bc495ee/services/commerce-api/src/modules/shipments/shipments.service.ts#L257), [carrier interface](https://github.com/Izyane-InovSolutions/commerce/blob/4e51b9a3f95cea84f25f524cd69dd0158bc495ee/services/commerce-api/src/modules/shipments/carrier-provider.interface.ts).

5. **Cart acceptance differs from #21.** Add/update persists over-stock quantities and reports the line unavailable, rather than rejecting that mutation. Checkout does revalidate stock. Separately, guest-cart ACTIVE state is read before the merge transaction; concurrent merges can both read ACTIVE and increment the account cart. The latter is a concurrency risk inferred from source, requiring a parallel-request database test. Evidence: [cart mutations](https://github.com/Izyane-InovSolutions/commerce/blob/4e51b9a3f95cea84f25f524cd69dd0158bc495ee/services/commerce-api/src/modules/cart/cart.service.ts#L54), [merge](https://github.com/Izyane-InovSolutions/commerce/blob/4e51b9a3f95cea84f25f524cd69dd0158bc495ee/services/commerce-api/src/modules/cart/cart.service.ts#L191).

6. **The media pipeline is a foundation, not complete delivery.** Signed URLs, local provider isolation and owner checks exist. Thumbnail processing, orphan cleanup and lifecycle audit are absent. Content type is compared with client-supplied MIME metadata rather than image-byte inspection. `FileInterceptor('file')` has no explicit multipart size limit; validating declared size at reservation does not stop an oversized multipart body being buffered. Evidence: [media service](https://github.com/Izyane-InovSolutions/commerce/blob/4e51b9a3f95cea84f25f524cd69dd0158bc495ee/services/commerce-api/src/modules/media/media.service.ts#L88), [multipart endpoint](https://github.com/Izyane-InovSolutions/commerce/blob/4e51b9a3f95cea84f25f524cd69dd0158bc495ee/services/commerce-api/src/modules/media/media.controller.ts#L55).

7. **Foundation/release requirements remain unresolved.** Caching/jobs are PostgreSQL-backed, not Redis. Outbox records have no relay/consumer; paid-order fulfillment is instead directly enqueued into the job queue. Rate limiting uses the default configured Nest throttler rather than a shared backend. No tracked `.github/workflows` directory was found. Docker deployment files and npm scripts do not establish the requested CI execution. Evidence: [B1], [B4], [cache](https://github.com/Izyane-InovSolutions/commerce/blob/4e51b9a3f95cea84f25f524cd69dd0158bc495ee/services/commerce-api/src/infrastructure/cache/cache.service.ts), [outbox](https://github.com/Izyane-InovSolutions/commerce/blob/4e51b9a3f95cea84f25f524cd69dd0158bc495ee/services/commerce-api/src/infrastructure/jobs/outbox.service.ts), [direct fulfillment enqueue](https://github.com/Izyane-InovSolutions/commerce/blob/4e51b9a3f95cea84f25f524cd69dd0158bc495ee/services/commerce-api/src/modules/orders/orders.service.ts#L614).

8. **Several backlog descriptions understate existing work.** #33 has a bulk inventory endpoint and validated publication; #38 has the complete backend review/moderation lifecycle; #58 already has effective price windows and immutable order snapshots; #61 already has a periodic payout worker with recovery. Missing live payout execution/risk scoring should not be described as a missing scheduler. Evidence: [B27], [B29], [B30], [B18].
